# Задача 1.1

s=14, k=3, M=4, L=7, d=3, q=5, epsilon=1/10000

## Принятые решения

Выбран единый формат состояний для памяти глубины d и сохраняемой случайной компоненты вместо отдельных форматов цепи Маркова и смеси. Исходные файлы задают цикл состояний. Грамматика и четыре примера приведены в `FORMAT.md`

Вероятности представлены `Fraction` вместо float, чтобы нормировка и вычисления были точными. При выборке знаменатели приводятся к общему D, исходу вероятности p отводятся p*D целых чисел из диапазона `randrange(D)`. Вероятность блока вычисляется переносом массы по состояниям после каждого символа

## Измерения

Python 3.11.14, seed=14, источник `examples/source14.json`, блок AB из `examples/word.json`

Переключатели задают P=(5/12,1/3,1/4) и R=(5/9,7/36,1/4), период P,R,P,P,R,R,P

Вероятность первого блока: `P(A)*R(B)=35/432=0.081018519`

Среднее по фазам: `[2*P(A)*R(B)+2*R(A)*P(B)+2*P(A)*P(B)+R(A)*R(B)]/7=85/648=0.131172840`

Частота считается по перекрывающимся блокам со знаменателем N-1. Все длины относятся к префиксам одной реализации, значения округлены до девяти знаков

| N | Частота AB | Отклонение от первой | Отклонение от средней |
| --- | --- | --- | --- |
| 100 | 0.111111111 | 0.030092593 | 0.020061728 |
| 1000 | 0.136136136 | 0.055117618 | 0.004963297 |
| 10000 | 0.137513751 | 0.056495233 | 0.006340912 |
| 100000 | 0.133111331 | 0.052092813 | 0.001938492 |
| 1000000 | 0.131273131 | 0.050254613 | 0.000100292 |

Частота сходится к среднему 85/648. Каждая фаза встречается с долей 1/L, а перекрывающиеся окна разбиваются на конечное число независимых подпоследовательностей с шагом, кратным L и не меньшим длины блока. Закон больших чисел даёт среднее фазовых вероятностей

В неэргодическом примере частота AB сходится к 1/6 в left или 1/18 в right при безусловной вероятности 1/9. При seed=14 выбрано left

При N <= 0, None или без N генерация останавливается нажатием Ctrl+C. Вывод программы на тестах приведён в `RESULTS.md`

# Задача 1.2

Для `examples/iid14.json` распределение P=(1/2,1/3,1/6), H=1.459147917027 бита на символ. Стационарность и отсутствие памяти проверяются точно через базис векторов состояний, включая расширенный формат

Выбран перебор типов вместо k^n слов. Тип c содержит `n!/prod(c[i]!)` слов вероятности `prod(P[i]**c[i])`. Типы сортируются по вероятности одного слова, затем отбирается до q^length слов, включая нужную часть последнего типа

Число типов `T(n)=C(n+k-1,k-1)`, при k=5 и n=50 их 316251. Время `O(k*nmax+sum(T(n)*log(T(n)+1)))`, память `O(T(nmax)+k*nmax)`. Вероятности приводятся к общему знаменателю, вычисления и сортировка выполняются на целых числах Python неограниченной разрядности, ошибка хранится как `Fraction`. Логарифмы вычисляются через `Decimal` с 80 значащими цифрами, длина при q=2^m точным делением

Измерения при q=5, epsilon=1/10000, nmax=50

| R | Минимальное n <= 50 | Условие для всех достаточно больших n |
| --- | --- | --- |
| 1 | нет | нет, R < H и ошибка стремится к 1 |
| 1.6 | 16 | да, R > H и ошибка стремится к 0 |

Для R=1.6 значения ошибки округлены до девяти знаков

| n | Длина кода | Pe(n) |
| --- | --- | --- |
| 1 | 0 | 0.500000000 |
| 3 | 2 | 0.013888889 |
| 15 | 10 | 0.014373491 |
| 16 | 11 | 0.000000000 |
| 17 | 11 | 0.068508823 |
| 50 | 34 | 0.000030382 |

Минимальное подходящее n не означает, что условие выполнено при всех следующих n: ошибка может возрастать из-за округления длины кода

При R < H подходящие малые n возможны. Для `tests/concentrated14.json` при R=0 и H=0.001473033528 ошибка Pe(1)=1/10000, а Pe(2)=19999/100000000 уже больше epsilon

При R=H неравномерного источника ошибка стремится к 1/2 снизу, поэтому n0 существует при epsilon >= 1/2 ([обоснование](https://www.dpmms.cam.ac.uk/~ik355/PAPERS/SVYK-J.pdf), теорема 17). Для равномерного источника учитывается округление: `Pe(n)=1-q**floor(n*log(k)/log(q))/k**n`

Время режима code на варианте 14: 0.014161 с. Полный запуск при k=5, nmax=50 на `tests/iid5.json`: 1.929272 с, что меньше 10 с

## Файл кода

В `code14.json` записаны алфавит в фиксированном порядке, распределение, q и описание кода для каждого n. Символы нулевой вероятности не кодируются

При `order=lex` кодируются первые `coded` слов в лексикографическом порядке. При `order=types` типы упорядочены по убыванию вероятности одного слова, при равенстве по возрастанию вектора количеств, слова внутри типа лексикографически. Все типы до `boundary.counts` включаются целиком, из граничного типа берутся первые `boundary.used` слов

Номер выбранного слова, начиная с 0, записывается в системе счисления с основанием q и дополняется слева нулями до `length` разрядов. Остальные слова вызывают ошибку декодирования
